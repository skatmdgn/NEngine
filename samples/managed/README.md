# C# SDK quickstart — NEngine 0.9.0-dev

These examples target the **NEngine C# API generated by this repository**, not Unity's scripting API. They are compile-checked as part of `NEngineScriptingTests` on CI with an available .NET SDK. The engine is not a production-ready 1.0 release.

## Create and compile a script

1. Open an NEngine project with a `NEngine.nproject` and an `Assets/Scripts` directory in the Windows Editor.
2. Copy [NavQuickstart.cs](NavQuickstart.cs) into `Assets/Scripts/NavQuickstart.cs`. Attach the `NavQuickstart` script type to an entity with a `NavMeshAgent` component and configure a compatible `.nnav` navigation asset.
3. Select **Scripts** to generate the `.nengine/Managed` solution. Select **Build C#** to invoke the .NET SDK and load/reload the gameplay assembly through `NEngine.Bridge`.
4. During Play, `StartCoroutine`, `WaitForSeconds`, `StopCoroutine`, `GetComponent<NavMeshAgent>()` and `SetDestination(Vector3)` are used by the sample. The navmesh must exist; the script cannot generate a navigation surface automatically.

## Third-party library references

The **Packages** panel edits `Packages/managed-packages.txt` as `PackageId Version` rows. **Build C#** regenerates the project and resolves those packages using the SDK's configured NuGet sources. Offline package builds can specify a project-local `NuGet.Config` feed. This is dependency **configuration**, not automatic download on selecting Install.

For a local managed assembly, place a valid `.dll` under `Assets/Plugins/Managed`. To use native P/Invoke dependencies, place platform-compatible `.dll`, `.so` or `.dylib` files under `Assets/Plugins/Native`. The actual third-party SDK license, native compatibility and runtime correctness remain the application's responsibility.

## Android settings

In **Build Settings**, target flags and the Android toolchain profile are stored in the project manifest. Enter SDK, NDK and JDK directories in the additional fields and select **Validate and Save SDK / NDK / JDK**. The validation checks SDK android-35, NDK 27.x metadata/CMake toolchain, and the platform JDK Java executable. This **does not** build or test an Android APK.

## Tested versus untested

The CI suite verifies managed source compilation, deterministic packaging, NuGet dependency graphs, exceptions, and console-level PlayerRuntime samples on Windows and Ubuntu. It does **not** validate an actual Windows GPU Editor session, a fully rendered Windows game, Rider/Visual Studio debugging, or Android device deployment. Track those separate acceptance IDs in [the checklist](../../docs/CHECKLIST.md).
